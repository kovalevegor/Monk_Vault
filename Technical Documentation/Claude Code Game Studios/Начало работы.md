## Часть 1 — Установка Claude Code

### Шаг 1. Установка пакета

Откройте PowerShell или командную строку и выполните:

```bash
npm install -g @anthropic-ai/claude-code
```

Проверьте установку:

```bash
claude --version
```

### Шаг 2. Получение API-ключа Anthropic

1. Перейдите на [console.anthropic.com](https://console.anthropic.com/)
2. Зарегистрируйтесь или войдите в аккаунт
3. Раздел **API Keys** → **Create Key**
4. Скопируйте ключ — он отображается только один раз

### Шаг 3. Авторизация Claude Code

```bash
claude
```

При первом запуске Claude Code запросит API-ключ. Вставьте его. После этого откроется интерактивная сессия в терминале.

## Часть 2 — Подключение шаблона к существующему проекту

У вас уже есть проект. Шаблон нужно не клонировать целиком, а скопировать его служебные файлы в корень вашего проекта.

### Шаг 4. Скачайте шаблон отдельно

```bash
git clone https://github.com/Donchitos/Claude-Code-Game-Studios.git ccgs-template
```

### Шаг 5. Скопируйте служебные файлы в ваш проект

Перейдите в папку вашего проекта и скопируйте следующее из `ccgs-template`:

```
ccgs-template/CLAUDE.md          →  ваш_проект/CLAUDE.md
ccgs-template/.claude/           →  ваш_проект/.claude/
```

В PowerShell:

```powershell
cd ваш_проект

Copy-Item "..\ccgs-template\CLAUDE.md" -Destination "."
Copy-Item "..\ccgs-template\.claude" -Destination "." -Recurse
```

### Шаг 6. Добавьте `.claude` в `.gitignore` (опционально)

Если не хотите коммитить конфигурацию агентов в репозиторий:

```
# .gitignore
.claude/
```

## Часть 3 — Первый запуск

### Шаг 7. Запустите сессию из папки проекта

```bash
cd ваш_проект
claude
```

### Шаг 8. Определите стадию проекта

Поскольку у вас существующий проект, первая команда:

```
/project-stage-detect
```

Агент проанализирует структуру файлов и определит, на какой стадии находится проект (прототип, альфа, производство и т.д.), после чего предложит релевантные следующие шаги.

Альтернатива — если хотите получить общую карту систем проекта:

```
/map-systems
```

## Часть 4 — Что такое агенты и как с ними работать

### Принцип работы

Claude Code Game Studios — это не плагин и не отдельная программа. Это набор конфигурационных файлов, которые структурируют поведение Claude Code внутри вашего проекта. Когда вы запускаете `claude` из папки проекта, он читает `CLAUDE.md` и папку `.claude/` и активирует всю систему агентов.

### Три уровня агентов

**Директора** — задают ограничения и разрешают конфликты между отделами. Напрямую вы с ними почти не взаимодействуете — они активируются автоматически при эскалации.

**Руководители отделов** — с ними вы общаетесь при постановке задач уровня фичи или системы. Например, `game-designer` при проектировании механики, `qa-lead` при подготовке к тестированию.

**Специалисты** — выполняют конкретные задачи: пишут код, создают документы, анализируют баланс. Вызываются напрямую или через командную цепочку.

### Как вызвать агента

В сессии Claude Code просто обращайтесь по имени:

```
@game-designer мне нужно спроектировать систему прогрессии для RPG
```

```
@lead-programmer проверь архитектуру модуля инвентаря
```

```
@qa-lead составь план тестирования для новой механики боя
```

### Как работают слэш-команды

Слэш-команды — это готовые рабочие процессы, каждый из которых вовлекает нужных агентов автоматически.

|Команда|Когда использовать|
|---|---|
|`/brainstorm`|Генерация и анализ игровых идей|
|`/design-review`|Ревью игрового дизайна или механики|
|`/code-review`|Ревью кода с проверкой стандартов|
|`/sprint-plan`|Планирование итерации|
|`/balance-check`|Анализ игровой экономики или баланса|
|`/perf-profile`|Анализ производительности|
|`/bug-report`|Структурированный разбор бага|
|`/tech-debt`|Аудит технического долга|
|`/prototype`|Проектирование прототипа фичи|

### Протокол взаимодействия

Агенты никогда не действуют самостоятельно. Каждый раз последовательность такая:

1. Агент задаёт уточняющие вопросы
2. Предлагает 2–4 варианта с плюсами и минусами
3. Ждёт вашего решения
4. Показывает черновик
5. Записывает результат только после вашего явного подтверждения

## Часть 5 — Хуки: что происходит автоматически

Хуки запускаются без вашего участия:

- При `git commit` — проверяется код на захардкоженные значения, формат TODO и корректность JSON
- При открытии сессии — загружается контекст проекта, обнаруживаются пробелы в документации
- При закрытии сессии — сохраняется журнал выполненного

Если `jq` не установлен — хуки просто пропускают соответствующие проверки, ничего не ломая. Установить `jq` на Windows можно через:

```bash
winget install jqlang.jq
```

## Рекомендуемый первый сеанс для существующего проекта

```
1. cd ваш_проект
2. claude
3. /project-stage-detect        ← определить стадию
4. /map-systems                 ← получить карту систем
5. /tech-debt                   ← выявить технический долг
6. /sprint-plan                 ← спланировать первую итерацию
```

Это даст полную картину состояния проекта и позволит сразу включить агентов в реальную работу, а не в демонстрационные задачи.
