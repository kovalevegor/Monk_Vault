Документация компонентной системы осмотра и сбора предметов. Описывает финальную архитектуру: компонент `AC_InteractionComponent`, базовый актор `BP_InspectableBase`, виджеты подсказки/предпросмотра/деталей, структуру данных предмета и схему ввода через Enhanced Input.

---
## 1. Обзор архитектуры

Система спроектирована независимой от конкретного класса персонажа. Вся логика взаимодействия инкапсулирована в `AC_InteractionComponent` (Actor Component). Персонаж выступает тонкой обёрткой: содержит компонент и делегирует ему события ввода. Интерактивные акторы не кастуются к конкретному классу персонажа, а находят компонент через `Get Component by Class`, что делает систему совместимой с любым владельцем — как `Pawn`, так и `Character`.

```
AC_InteractionComponent        ← вся логика, переменные, функции взаимодействия
    ├── управляет виджетами (подсказка, предпросмотр, детали)
    ├── управляет Input Mapping Context (добавление/снятие)
    └── обрабатывает делегированные события ввода

BP_InspectableBase (Actor)     ← реализует BPI_Interactable
    ├── находит AC_InteractionComponent у вошедшего актора
    └── вызывает функции компонента (без Cast к персонажу)
        └── дочерние BP_* — конкретные предметы (данные через ItemData)

Персонаж (Pawn или Character)  ← содержит AC_InteractionComponent
    └── 4 делегирующих блока ввода → вызывают функции компонента
```
— 
### Поток данных

1. Игрок входит в зону предмета → `BeginOverlap` находит компонент → показывается подсказка `[E] Осмотреть`, компонент запоминает интерактивный объект и добавляет `IMC_Interaction`.
2. Игрок нажимает кнопку взаимодействия → вызывается `Interact` на объекте через интерфейс → объект показывает виджет предпросмотра.
3. Игрок удерживает кнопку → накапливается прогресс, заполняется кольцо → по достижении порога открывается виджет деталей, снимаются gameplay-контексты ввода.
4. Игрок нажимает кнопку выхода → виджет деталей закрывается, ввод восстанавливается; collectable-предмет скрывается с уровня.
5. Игрок покидает зону → подсказка и предпросмотр скрываются, `IMC_Interaction` снимается.

## 2. Структура данных — FS_ItemData

Структура-контейнер данных предмета. Используется виджетами и актором.

|Поле|Тип|Назначение|
|---|---|---|
|`ItemName`|Text|Название предмета|
|`ShortPrompt`|Text|Фраза-подсказка в предпросмотре (например, «Удержите для осмотра»)|
|`FullDescription`|Text|Полное описание в окне деталей|
|`MiniImage`|Texture2D (Object Reference)|Миниатюра в предпросмотре|
|`LargeImage`|Texture2D (Object Reference)|Крупное изображение в деталях|

---

## 3. Интерфейс — BPI_Interactable

Blueprint Interface с единственной функцией `Interact` (без параметров). Контракт, позволяющий вызывать взаимодействие на любом акторе, реализующем интерфейс, без знания его конкретного класса. Реализуется в `BP_InspectableBase`; вызывается из компонента через типизированный вызов на ссылке типа `BPI_Interactable`.

## 4. Виджеты

### 4.1 WBP_Interact (базовый) и WBP_Examine (дочерний)

`WBP_Interact` — базовая подсказка взаимодействия: фон-клавиша и текст действия. Текст действия хранится в переменной `ActionLabel` (Text, Instance Editable, Expose on Spawn) и привязан к текстовому блоку через binding.

`WBP_Examine` — дочерний от `WBP_Interact`, создан как Blueprint Class на базе родителя. В `Event Pre Construct` устанавливает `ActionLabel` = «Осмотреть». Это та подсказка, что показывается при входе в зону предмета.

### 4.2 WBP_ExaminePrompt (предпросмотр)

Второй виджет — появляется после нажатия кнопки взаимодействия. Содержит миниатюру, название, фразу-подсказку и кольцо прогресса удержания.

**Структура вёрстки:**

```
Canvas Panel (на весь экран)
├── Vertical Box (центр-снизу)
│   ├── Image     — MiniImage (миниатюра)
│   ├── Text      — ItemNameText (название)
│   └── Text      — PromptText (фраза-подсказка)
└── Image         — RingImage (кольцо прогресса, материал M_RingProgress)
```

**Переменные:** `ItemData` (FS_ItemData, Expose on Spawn), `RingMaterialInstance` (Material Instance Dynamic).

**Event Construct:**

1. `Create Dynamic Material Instance` (Source = `M_RingProgress`) → сохраняется в `RingMaterialInstance`.
2. `Set Brush from Material` (Target = `RingImage`, Material = `RingMaterialInstance`).
3. `Break FS_ItemData` от `ItemData` → заполняются `ItemNameText` (ItemName), `PromptText` (ShortPrompt), `MiniImage` (Set Brush from Texture = MiniImage).

**Функция UpdateRing(Progress: Float):** вызывает `Set Scalar Parameter Value` на `RingMaterialInstance`, параметр `Progress`. Управляет заполнением кольца.

### 4.3 WBP_ExamineDetail (детали)

Третий виджет — полноэкранное окно с подробной информацией. Открывается после удержания.

**Структура вёрстки:**

```
Canvas Panel (на весь экран)
├── Border        — полупрозрачный чёрный фон (RGBA 0,0,0,0.8)
└── Vertical Box (центр)
    ├── Image      — LargeImage (крупное изображение)
    ├── Text       — DetailNameText (название)
    ├── Scroll Box
    │   └── Text   — DescriptionText (полное описание, Auto Wrap)
    └── Text       — статичная подпись выхода
```

**Переменные:** `ItemData` (FS_ItemData, Expose on Spawn).

**Event Construct:** `Break FS_ItemData` → `DetailNameText` (ItemName), `DescriptionText` (FullDescription), `LargeImage` (Set Brush from Texture = LargeImage).

### 4.4 Материал кольца — M_RingProgress

Материал прогресс-кольца. Параметры материала: `Material Domain` = User Interface, `Blend Mode` = Translucent.

Логика: по UV-координатам вычисляется угол пикселя относительно центра (через `Arctangent2`, нормализация в диапазон 0..1) и его радиус (через расстояние от центра). Маска кольца формируется парой границ радиуса (внешняя и внутренняя). Маска прогресса — сравнением нормализованного угла со скалярным параметром `Progress`. Итоговая маска (кольцо × прогресс) умножается на цвет и подаётся в Final Color и Opacity. Параметр `Progress` (Scalar) управляется извне через `UpdateRing`.

## 5. Компонент — AC_InteractionComponent

Ядро системы. Содержит все переменные состояния, функции управления виджетами и вводом, а также обработчики делегированных событий.

### 5.1 Переменные

|Имя|Тип|Default|Instance Editable|Назначение|
|---|---|---|---|---|
|`CurrentInteractable`|BPI_Interactable (Object Reference)|—|нет|Текущий объект в зоне|
|`InteractWidgetInstance`|User Widget (Object Reference)|—|нет|Экземпляр подсказки|
|`bExaminePromptActive`|Boolean|false|нет|Флаг: открыт предпросмотр|
|`bExamineDetailActive`|Boolean|false|нет|Флаг: открыты детали|
|`HoldProgress`|Float|0.0|нет|Прогресс удержания (0..1)|
|`HoldDuration`|Float|1.0|да|Длительность удержания до открытия деталей|
|`ExaminePromptWidget`|WBP_ExaminePrompt (Object Reference)|—|нет|Экземпляр предпросмотра|
|`ExamineDetailWidget`|WBP_ExamineDetail (Object Reference)|—|нет|Экземпляр деталей|
|`AutoDismissTimerHandle`|Timer Handle|—|нет|Таймер автоскрытия предпросмотра|
|`CurrentItemData`|FS_ItemData|—|нет|Данные текущего предмета|
|`LastInspectedActor`|Actor (Object Reference)|—|нет|Осматриваемый актор (для скрытия collectable)|
|`bCurrentItemIsCollectable`|Boolean|false|нет|Флаг collectable текущего предмета|
|`InteractionIMC`|Input Mapping Context (Object Reference)|—|да|Контекст ввода взаимодействия|
|`GameplayIMC`|Input Mapping Context (Array)|—|да|Список gameplay-контекстов, снимаемых на время деталей|

### 5.2 Функции управления подсказкой

**ShowExamineInteractWidget** — создаёт `WBP_Examine`, сохраняет в `InteractWidgetInstance`, проверяет валидность и добавляет на экран (`Add to Viewport`, ZOrder = 10). Жёстко задан класс виджета.

**HideInteractWidget** — если `InteractWidgetInstance` валиден, удаляет его (`Remove from Parent`) и обнуляет переменную.

**SetCurrentInteractable(Interactable: BPI_Interactable)** — сохраняет ссылку в `CurrentInteractable`; затем получает Enhanced Input Subsystem (Get Player Controller → Get Local Player → Get Subsystem), проверяет валидность и добавляет `InteractionIMC` с приоритетом 1.

**ClearCurrentInteractable** — обнуляет `CurrentInteractable`, вызывает `HideInteractWidget` и `HideExaminePrompt`; затем снимает `InteractionIMC` через `Remove Mapping Context`.

### 5.3 Функции предпросмотра

**ShowExaminePrompt(InItemData, bAutoDismiss, InActor, bIsCollectable)** — последовательность:

1. `HideInteractWidget` (убрать подсказку);
2. `Set LastInspectedActor` = InActor, `Set bCurrentItemIsCollectable` = bIsCollectable;
3. `Set CurrentItemData` = InItemData, `Set bExaminePromptActive` = true, `Set HoldProgress` = 0.0;
4. `Create Widget` (`WBP_ExaminePrompt`, ItemData = CurrentItemData) → сохранить в `ExaminePromptWidget` → `Add to Viewport` (ZOrder = 20);
5. если `bAutoDismiss` = true → `Set Timer by Event` (5 сек, не зацикленный) на событие автоскрытия, handle в `AutoDismissTimerHandle`.

**HideExaminePrompt** — сбрасывает `bExaminePromptActive` = false и `HoldProgress` = 0.0; если `ExaminePromptWidget` валиден — удаляет его и обнуляет; очищает таймер автоскрытия.

### 5.4 Функции деталей

**ShowExamineDetail** — последовательность:

1. `HideExaminePrompt`;
2. `Set bExamineDetailActive` = true;
3. `Create Widget` (`WBP_ExamineDetail`, ItemData = CurrentItemData) → сохранить в `ExamineDetailWidget` → `Add to Viewport` (ZOrder = 30);
4. снять gameplay-ввод: получить Subsystem → `For Each Loop` по `GameplayIMC` → `Remove Mapping Context` для каждого элемента.

**HideExamineDetail** — последовательность (возврат ввода стоит первым для гарантированного выполнения):

1. вернуть gameplay-ввод: получить Subsystem → `For Each Loop` по `GameplayIMC` → `Add Mapping Context` (Priority = 0) для каждого элемента;
2. `Set bExamineDetailActive` = false;
3. если `ExamineDetailWidget` валиден — удалить и обнулить;
4. `Branch(bCurrentItemIsCollectable)`:
    - True → `Cast to BP_InspectableBase` (Object = `LastInspectedActor`) → `Set Actor Hidden In Game` = true → `Get InteractZone` → `Set Collision Enabled` = No Collision → `Clear Current Interactable`;
5. сброс: `Set bCurrentItemIsCollectable` = false, `Set LastInspectedActor` = None.

### 5.5 Обработчики ввода (делегаты)

Эти функции вызываются персонажем в ответ на события Enhanced Input. Вся логика — внутри компонента.

**HandleInteractTriggered** — реакция на нажатие кнопки взаимодействия:

```
Branch(bExamineDetailActive)
    True  → (ничего — детали закрываются только кнопкой выхода)
    False → Branch(bExaminePromptActive)
                True  → (ничего — предпросмотр уже открыт)
                False → Branch(Is Valid CurrentInteractable)
                            True → Interact (вызов интерфейса на CurrentInteractable)
```

**HandleHoldOngoing** — реакция на удержание (срабатывает каждый кадр пока кнопка зажата):

```
Branch(bExaminePromptActive)
    True → Branch(bExamineDetailActive)
                False → HoldProgress = Clamp(HoldProgress + WorldDeltaSeconds / HoldDuration, 0, 1)
                       → Branch(Is Valid ExaminePromptWidget)
                           True → UpdateRing(HoldProgress)
                                → Branch(HoldProgress >= 1.0)
                                    True → ShowExamineDetail
```

**HandleHoldCompleted** — реакция на отпускание кнопки:

```
Branch(bExaminePromptActive AND NOT bExamineDetailActive)
    True → HoldProgress = 0.0
         → Branch(Is Valid ExaminePromptWidget)
             True → UpdateRing(0.0)
```

**HandleExitTriggered** — реакция на кнопку выхода:

```
Branch(bExamineDetailActive)
    True → HideExamineDetail
```

## 6. Базовый актор — BP_InspectableBase

Актор интерактивного предмета. Реализует `BPI_Interactable`. Дочерние Blueprint задают конкретные данные.

### 6.1 Компоненты

```
InspectBase (Scene Component, Root)
├── ItemMesh (Static Mesh Component)
└── InteractZone (Sphere Collision, Radius 200, Overlap только Pawn)
```

### 6.2 Переменные

|Имя|Тип|Instance Editable|Назначение|
|---|---|---|---|
|`ItemData`|FS_ItemData|да|Данные предмета|
|`bIsCollectable`|Boolean|да|Исчезает ли предмет после осмотра|

### 6.3 BeginOverlap (InteractZone)

```
Other Actor
    → Get Component by Class (AC_InteractionComponent)
        → Is Valid (Return Value)
            → Show Examine Interact Widget (Target = компонент)
            → Set Current Interactable (Target = компонент, Interactable = Self)
```

### 6.4 EndOverlap (InteractZone)

```
Other Actor
    → Get Component by Class (AC_InteractionComponent)
        → Is Valid (Return Value)
            → Clear Current Interactable (Target = компонент)
```

### 6.5 Event Interact (реализация интерфейса)

```
Get Player Pawn
    → Get Component by Class (AC_InteractionComponent)
        → Is Valid
            → Branch(bIsCollectable)
                True  → Show Examine Prompt (ItemData, bAutoDismiss=true,  InActor=Self, bIsCollectable=true)
                False → Show Examine Prompt (ItemData, bAutoDismiss=false, InActor=Self, bIsCollectable=false)
```

Предмет не скрывается в момент нажатия — скрытие collectable выполняется при закрытии деталей (см. 5.4 `HideExamineDetail`).

### 6.6 Дочерние предметы

Создаются как Child Blueprint Class от `BP_InspectableBase`. В Class Defaults задаются: `ItemMesh` (Static Mesh), поля `ItemData` (ItemName, ShortPrompt, FullDescription, MiniImage, LargeImage), флаг `bIsCollectable`. Логику дочерние акторы не содержат.

## 7. Схема ввода — Enhanced Input

### 7.1 Input Actions

|Action|Value Type|Назначение|
|---|---|---|
|`IA_Interact`|Digital (bool)|Нажатие взаимодействия (ЛКМ)|
|`IA_HoldInteract`|Digital (bool)|Удержание для осмотра (ЛКМ)|
|`IA_Exit`|Digital (bool)|Выход из деталей (ПКМ)|

### 7.2 IMC_Interaction

Контекст взаимодействия. Добавляется компонентом при входе в зону (приоритет 1), снимается при выходе.

|Action|Клавиша|Триггеры|
|---|---|---|
|`IA_Interact`|Left Mouse Button|—|
|`IA_HoldInteract`|Left Mouse Button|— (срабатывает каждый кадр пока зажата)|
|`IA_Exit`|Right Mouse Button|—|

Накопление прогресса реализовано на фазе `Triggered` у `IA_HoldInteract` (без явного триггера действие удовлетворяется каждый кадр), а не на `Ongoing`.

### 7.3 Gameplay-контексты (GameplayIMC)

Контексты движения и камеры (например, `IMC_Default`, `IMC_MouseLook`) перечисляются в массиве `GameplayIMC` компонента. На время открытия деталей они снимаются (`ShowExamineDetail`) и возвращаются при закрытии (`HideExamineDetail`). `IMC_Interaction` при этом остаётся активным, поэтому `IA_Exit` (ПКМ) продолжает работать.

## 8. Полный жизненный цикл взаимодействия

```
Вход в зону (BeginOverlap)
    → Get Component → Show Examine Interact Widget → подсказка [E] Осмотреть
    → Set Current Interactable → +IMC_Interaction (priority 1)

Нажатие ЛКМ (IA_Interact: Triggered)
    → HandleInteractTriggered
    → детали неактивны, предпросмотр неактивен, CurrentInteractable валиден
    → Interact (интерфейс) → актор вызывает Show Examine Prompt
    → HideInteractWidget (убрать подсказку) → показать WBP_ExaminePrompt

Удержание ЛКМ (IA_HoldInteract: Triggered, каждый кадр)
    → HandleHoldOngoing
    → HoldProgress растёт → UpdateRing (заполнение кольца)
    → HoldProgress >= 1.0 → Show Examine Detail
        → HideExaminePrompt → показать WBP_ExamineDetail (ZOrder 30)
        → снять GameplayIMC (движение и камера заблокированы)

Отпускание ЛКМ до завершения (IA_HoldInteract: Completed)
    → HandleHoldCompleted → HoldProgress = 0 → UpdateRing(0)

Нажатие ПКМ (IA_Exit: Triggered)
    → HandleExitTriggered → Hide Examine Detail
        → вернуть GameplayIMC (управление восстановлено)
        → убрать WBP_ExamineDetail
        → если collectable: скрыть актор, отключить коллизию, Clear Current Interactable

Выход из зоны (EndOverlap)
    → Get Component → Clear Current Interactable
        → HideInteractWidget, HideExaminePrompt
        → -IMC_Interaction
```

## 9. Перенос системы на нового персонажа

Система не требует изменений в интерактивных акторах и виджетах при смене персонажа. Достаточно действий на стороне персонажа:

```
1. Components → Add → AC_InteractionComponent
2. AC_InteractionComponent → Details:
     InteractionIMC = IMC_Interaction
     GameplayIMC    = [ IMC_Default, IMC_MouseLook ]   (контексты движения/камеры)
3. BeginPlay → Add Mapping Context (gameplay-IMC, Priority = 0)
     (IMC_Interaction вручную НЕ добавлять — им управляет компонент)
4. Event Graph — четыре делегирующих блока (по три ноды):
     IA_Interact     : Triggered → Get AC_InteractionComponent → HandleInteractTriggered
     IA_HoldInteract : Triggered → Get AC_InteractionComponent → HandleHoldOngoing
     IA_HoldInteract : Completed → Get AC_InteractionComponent → HandleHoldCompleted
     IA_Exit         : Triggered → Get AC_InteractionComponent → HandleExitTriggered
```

Совместимость с любым владельцем (`Pawn` или `Character`) обеспечивается тем, что акторы находят компонент через `Get Component by Class`, а не через Cast к конкретному классу.
