### 1. **Ветки (branch naming)**

Чаще всего используют структуру: 

```
<тип>/<краткое-описание>
```

#### Типы веток:

|Тип ветки|Пример|Когда использовать|
|---|---|---|
|`feature`|`feature/login-form`|Новая фича или функционал|
|`bugfix`|`bugfix/fix-crash`|Исправление багов|
|`hotfix`|`hotfix/security-patch`|Срочные исправления в проде|
|`release`|`release/1.2.0`|Подготовка релиза|
|`chore`|`chore/update-deps`|Сопутствующие задачи (обновления, настройки)|

**Рекомендации по названию ветки:**

- Использовать **маленькие буквы** и дефисы вместо пробелов (`-`), не использовать подчеркивания.
- Кратко и ясно описывать цель ветки, без лишней информации.
- По возможности включать **номер задачи/тикета** в Jira/GitHub/GitLab:
    

```
feature/123-login-form
```

### 2. **Коммиты (commit messages)**

Стандарт часто используют такой (вдохновлен Conventional Commits):

```
<тип>(<область>): <краткое описание>
<подробное описание (опционально)>
<footer>
```

#### Типы:

|Тип|Пример сообщения|Когда использовать|
|---|---|---|
|`feat`|`feat(auth): add login form`|Добавление функционала|
|`fix`|`fix(cart): correct total price calc`|Исправление багов|
|`docs`|`docs(readme): update installation`|Изменения документации|
|`style`|`style(button): fix indentation`|Форматирование, пробелы, стиль кода|
|`refactor`|`refactor(api): simplify request logic`|Рефакторинг без изменения функционала|
|`chore`|`chore(deps): update lodash to 4.17.21`|Сопутствующие задачи, обновления|

**Правила для сообщения:**

1. Первая строка ≤ 50 символов, глагол в **повелительном наклонении** (`Add`, `Fix`, `Update`).
2. Пустая строка после заголовка.
3. Подробное описание — до 72 символов в строке.
4. Можно добавить `Closes #123` или `Refs #123` в футер, чтобы связывать коммит с задачей.
