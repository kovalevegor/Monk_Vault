Положение в основу игры метафоры о буддистской догме непривязанности, на которой строятся механики, нарративный дизайн и дизайн квестов.


---
## Art Direction
Подбор референсов, проведение визуальных исследований в областях архитектуры, традиционной одежды и культуры Тибета, а также курирование визуального направления.

---
## Сеттинг
Создание оригинального фэнтези-сеттинга, вдохновленного тибетской культурой, где **карма** является измеримой физической и экономической силой. Создание мира, где сосуществуют буддийская традиция и древние верования **Бон**. Социальная иерархия и внешность людей напрямую зависят от уровня их перерождения, а духовные заслуги служат валютой, необходимой для торговли и политики. Глубинный конфликт связан с деятельностью **черных монахов**, которые насильственно отщепляют чужую карму, создавая «опустошенных» людей и загрязняя реальность бесхозной кармой.

## Проблема 1 — CurrentInteractable: ошибка типа

**Причина:** переменная `CurrentInteractable` в компоненте объявлена с типом `BPI_Interactable` (интерфейс). Ноды `Is Valid` и `Interact (Message)` ожидают тип `Actor`. Нужно сменить тип переменной.

**Исправление:**

Открыть `AC_InteractionComponent` → My Blueprint → Variables → `CurrentInteractable`. В Details → Variable Type → изменить на **Actor** → **Object Reference**. Compile → переподключить оборванные провода.

В `HandleInteractTriggered`:

- Нода проверки: стандартный `Is Valid` (не Interface-версия) — пин `Object`: Get `CurrentInteractable`
- Нода вызова: `Interact (Message)` — Target: Get `CurrentInteractable`

`Interact (Message)` с `Actor`-типом работает корректно — движок находит реализацию интерфейса в рантайме.

## Проблема 2 — Return Value несовместим с Target нод функций

**Причина:** ноды `Set Current Interactable`, `Clear Current Interactable`, `Show Examine Prompt` в `BP_InspectableBase` ещё указывают на старые функции `SandboxCharacter_Mover`. Тип Target у них — `SandboxCharacter_Mover`, поэтому `AC_InteractionComponent` не подходит.

**Исправление для каждой ноды во всех затронутых Blueprint:**

**Шаг 1.** Удалить старую ноду (`Set Current Interactable` / `Clear Current Interactable` / `Show Examine Prompt` / `Show Chop Tree Interact Widget`).

**Шаг 2.** От синего выхода `Return Value` ноды `Get Component by Class` → потянуть провод → в поиске написать название функции (`Set Current Interactable` и т.д.) → выбрать вариант **с пометкой Target is AC Interaction Component**. Target подставляется автоматически.

**Шаг 3.** Переподключить белые провода выполнения и синие провода параметров (Self → Interactable, ItemData → InItemData и т.д.).

Применить для всех Blueprint: `BP_InspectableBase` (BeginOverlap, EndOverlap, Event Interact), `BP_FallenTree` (BeginOverlap, EndOverlap).

## Проблема 3 — Недостающие функции-делегаты

Да, `Completed` и `Exit` тоже нужно выносить в компонент. Добавить в `AC_InteractionComponent`:

**Функция `HandleHoldCompleted`** — логика из `IA_HoldInteract: Completed`:

```
Branch(bExaminePromptActive AND NOT bExamineDetailActive)
    True:
        → Set HoldProgress = 0.0
        → Branch(Is Valid ExaminePromptWidget)
            True → UpdateRing(Progress = 0.0)
```

**Функция `HandleExitTriggered`** — логика из `IA_Exit: Triggered`:

```
Branch(bExamineDetailActive)
    True → HideExamineDetail
```

В `SandboxCharacter_Mover` Event Graph:

- `IA_HoldInteract: Completed` → Get Component → `HandleHoldCompleted`
- `IA_Exit: Triggered` → Get Component → `HandleExitTriggered`

**Compile.**

## Смена клавиш: E → ЛКМ, удержание → ЛКМ, выход → ПКМ

Открыть IMC. Изменить маппинги:

|Input Action|Старая клавиша|Новая клавиша|
|---|---|---|
|`IA_Interact`|E|`Left Mouse Button`|
|`IA_HoldInteract`|E|`Left Mouse Button`|
|`IA_Exit`|Q|`Right Mouse Button`|

Триггеры не трогать — `IA_Interact` остаётся без явного триггера (Down), `IA_HoldInteract` остаётся без явного триггера (Down).

**Save.**

> **Предупреждение:** если ЛКМ используется для других действий (атаки, прицела) — потребуется добавить условие в `HandleInteractTriggered`, исключающее ложные срабатывания. Уточните когда потребуется.

## Итоговая схема добавления компонента на нового персонажа

**Шаг 1. Добавить компонент:** Components → Add → `AC_InteractionComponent`.

**Шаг 2. Добавить IMC в BeginPlay:**

Если у персонажа есть `SetupInput` или `BeginPlay`: убедиться что там вызывается `Add Mapping Context` с IMC, содержащим `IA_Interact`, `IA_HoldInteract`, `IA_Exit`. Если IMC уже добавляется для других действий — просто убедиться что три IA присутствуют в нём.

**Шаг 3. Добавить 5 нодов в Event Graph:**

```
[IA_Interact: Triggered]   → Get AC_InteractionComponent → HandleInteractTriggered
[IA_HoldInteract: Triggered] → Get AC_InteractionComponent → HandleHoldOngoing
[IA_HoldInteract: Completed] → Get AC_InteractionComponent → HandleHoldCompleted
[IA_Exit: Triggered]       → Get AC_InteractionComponent → HandleExitTriggered
```

Получение компонента — в каждом блоке: перетащить `AC_InteractionComponent` из панели Components → Get.

Это всё что нужно для нового персонажа. Все Blueprint объектов (`BP_InspectableBase`, `BP_FallenTree` и будущие) не трогаются.
