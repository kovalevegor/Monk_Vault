**Вся логика построена через флоуграф. Фактически граф не хранит в себе никакой информации, он только следит за последовательностью выполняемых действий**  
  
**игрок взаимодействует с персонажем - персонаж отправляет в флоуграф запрос, есть ли для него сейчас действие - флоуграф возвращает в персонажа тег взаимодействия, если такой сейчас доступен - персонаж начинает взаимодействие внутри себя** 

# **Как настроить** 

**Есть перент BP_NPC_Base  Blueprint class** 
**От него делать чайлд актора**

**В чайлд акторе зайти в Flow компонент**

**В деталях задать ему персональный тег NPC**

**Перейти в Class Defaults в блупринте чайлда**

**В Default группе найти NPC Dialogue Tag.** 

**Это тег, которым непись стучится в граф. Если тег диалога/интеракции имеет на конце числовое значение, то тег непися его НЕ ИМЕЕТ. Просто Monk.Dialogue.Monastery.Test**  
  
**НЕ   Monk.Dialogue.Monastery.Test.01**

**Как подключить это к графу**  
  
**Найти FA_Monastery_01, просто нажми на папку с лупой вот тут**  

**Открой вот эту штуку FA_Monastery_01**

**Вот так выглядит последовательность из двух диалогов**


1. **Главная связь (основной поток)**  
   - **Из ноды «Monk Characters Lhamo.01» (тип, вероятно, персонаж или контроллер диалога) выходит провод «On Notify From Actor».**  
   - **Этот провод идёт на вход ноды «Monk Dialogue Monastery Lhamo.01» (диалоговая нода).**  
   - **На этой диалоговой ноде вход называется «Start» (или же выбор в событии: *Start*, *Stop*).**  
   - **То есть: *персонаж-монах* уведомляет *диалог в монастыре*, и диалог запускается.**

1. **Завершение диалога (обратная связь)**  
   - **Из той же диалоговой ноды «Monk Dialogue Monastery Lhamo.01» есть выход «Completed», который ведёт к пинам «Success» / «Stopped».**  
   - **Судя по схеме, эти пины соединены с «Notify Actor» (вероятно, нотификация обратно в Monk Characters Lhamo.01).**  
   - **То есть: когда диалог завершён (успешно или остановлен), персонаж получает об этом уведомление.**

1. **Вторая пара нод (тестовый вариант)**  
   - **«Monk Characters Test.01» → провод «On Notify From Actor» → идёт на «Monk Dialogue Monastery Test.01» (вход «Start»).**  
   - **Далее выход «Completed» (пины *Success*, *Stop*) из тестового диалога идут обратно через «Notify Actor» к тестовому персонажу.**  
   - **Причём на «On Notify From Actor» у тестового диалога дополнительно есть вход «Stop», что позволяет персонажу прервать диалог.**

**Итог по проводам словами:**  
**От персонажа (Lhamo) идёт провод уведомления в диалог (запуск). От диалога идёт провод завершения обратно к персонажу (успех/остановка). Та же логика повторяется для тестовой пары персонаж–диалог, но с явным пином Stop на стороне диалога.**
