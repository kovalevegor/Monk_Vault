## Для чего это нужно

Разрабатывать игру в одиночку с помощью ИИ эффективно — но одна чат-сессия лишена структуры. Никто не остановит вас от захардкоживания магических чисел, пропуска проектной документации или написания спагетти-кода. Нет ни прохода QA, ни ревью дизайна, ни вопроса «а соответствует ли это вообще видению игры?»

**Claude Code Game Studios** решает эту проблему, придавая вашей ИИ-сессии структуру реальной студии. Вместо одного универсального ассистента вы получаете 48 специализированных агентов, организованных в иерархию студии: директора, хранящие видение проекта; руководители отделов, отвечающие за свои домены; и специалисты, выполняющие непосредственную работу. У каждого агента определены зоны ответственности, пути эскалации и критерии качества.

Результат: вы по-прежнему принимаете все решения, но теперь у вас есть команда, которая задаёт правильные вопросы, выявляет ошибки на ранних этапах и поддерживает организованность проекта от первого брейнсторма до релиза.

## Начало работы

### Предварительные требования

- [Git](https://git-scm.com/)
- [Claude Code](https://docs.anthropic.com/en/docs/claude-code) (`npm install -g @anthropic-ai/claude-code`)
- **Рекомендуется**: [jq](https://jqlang.github.io/jq/) (для валидации хуков) и Python 3 (для валидации JSON)

Все хуки деградируют корректно при отсутствии опциональных инструментов — работоспособность системы не нарушается, теряется только валидация.

### Установка

1. **Клонируйте репозиторий или используйте как шаблон**:
    
```bash
    git clone https://github.com/Donchitos/Claude-Code-Game-Studios.git my-game
    cd my-game
```
    
2. **Откройте Claude Code** и запустите сессию:
    
```bash
    claude
```
    
3. **Выполните `/start`** — система уточнит, на каком этапе вы находитесь (нет идеи, есть расплывчатая концепция, чёткий дизайн, уже есть наработки) и направит к подходящему рабочему процессу. Никаких предположений.
    
    Или перейдите сразу к конкретному навыку, если знаете, что нужно:
    
    - `/brainstorm` — генерация игровых идей с нуля
    - `/setup-engine godot 4.6` — настройка движка, если он уже выбран
    - `/project-stage-detect` — анализ существующего проекта

## Как это работает

### Координация агентов

Агенты следуют структурированной модели делегирования:

1. **Вертикальное делегирование** — директора делегируют руководителям, руководители — специалистам
2. **Горизонтальная консультация** — агенты одного уровня могут консультироваться, но не принимать обязывающих межведомственных решений
3. **Разрешение конфликтов** — разногласия эскалируются к общему родительскому агенту (`creative-director` для дизайна, `technical-director` для технических вопросов)
4. **Распространение изменений** — межведомственные изменения координирует `producer`
5. **Границы доменов** — агенты не модифицируют файлы за пределами своего домена без явного делегирования

### Совместная работа, а не автопилот

Это **не** система автономного выполнения задач. Каждый агент следует строгому протоколу взаимодействия:

1. **Вопросы** — агенты задают вопросы перед предложением решений
2. **Варианты** — агенты предлагают 2–4 варианта с плюсами и минусами
3. **Ваше решение** — итоговый выбор всегда за пользователем
4. **Черновик** — агенты показывают работу до её финализации
5. **Утверждение** — ничто не записывается без вашего одобрения

Вы сохраняете контроль. Агенты обеспечивают структуру и экспертизу, а не автономность.

### Автоматизированная безопасность

**Хуки** запускаются автоматически при каждой сессии:

|Хук|Триггер|Что делает|
|---|---|---|
|`validate-commit.sh`|`git commit`|Проверяет захардкоженные значения, формат TODO, корректность JSON, разделы проектных документов|
|`validate-push.sh`|`git push`|Предупреждает при пуше в защищённые ветки|
|`validate-assets.sh`|Запись файлов в `assets/`|Валидирует соглашения об именовании и структуру JSON|
|`session-start.sh`|Открытие сессии|Загружает контекст спринта и последнюю активность в git|
|`detect-gaps.sh`|Открытие сессии|Обнаруживает новые проекты (предлагает `/start`) и отсутствующую документацию при наличии кода или прототипов|
|`pre-compact.sh`|Сжатие контекста|Сохраняет заметки о прогрессе сессии|
|`session-stop.sh`|Закрытие сессии|Записывает результаты работы|
|`log-agent.sh`|Запуск агента|Журнал аудита всех вызовов субагентов|

**Правила разрешений** в `settings.json` автоматически разрешают безопасные операции (git status, запуск тестов) и блокируют опасные (force push, `rm -rf`, чтение файлов `.env`).

### Правила, привязанные к путям

Стандарты кода применяются автоматически в зависимости от расположения файла:

|Путь|Требования|
|---|---|
|`src/gameplay/**`|Значения через данные, использование delta time, отсутствие ссылок на UI|
|`src/core/**`|Нулевые аллокации в горячих путях, потокобезопасность, стабильность API|
|`src/ai/**`|Бюджеты производительности, отлаживаемость, параметры через данные|
|`src/networking/**`|Авторитетный сервер, версионированные сообщения, безопасность|
|`src/ui/**`|Отсутствие владения игровым состоянием, готовность к локализации, доступность|
|`design/gdd/**`|Обязательные 8 разделов, формат формул, граничные случаи|
|`tests/**`|Именование тестов, требования к покрытию, паттерны фикстур|
|`prototypes/**`|Смягчённые стандарты, обязательный README, задокументированная гипотеза|

## Философия дизайна

Шаблон опирается на профессиональные практики разработки игр:

- **MDA-фреймворк** — анализ Механик, Динамики и Эстетики для игрового дизайна
- **Теория самодетерминации** — Автономия, Компетентность, Связанность для мотивации игрока
- **Дизайн состояния потока** — баланс сложности и навыков для вовлечённости игрока
- **Типы игроков Бартла** — таргетирование и валидация аудитории
- **Разработка через верификацию** — сначала тесты, затем реализация

## Кастомизация

Это **шаблон**, а не закрытый фреймворк. Всё предназначено для настройки под ваши нужды:

- **Добавление/удаление агентов** — удалите ненужные файлы агентов, добавьте новые для своих доменов
- **Редактирование промптов агентов** — настройте поведение, добавьте специфичные для проекта знания
- **Изменение навыков** — адаптируйте рабочие процессы под методологию вашей команды
- **Добавление правил** — создайте новые правила, привязанные к путям, для структуры директорий вашего проекта
- **Настройка хуков** — отрегулируйте строгость валидации, добавьте новые проверки
- **Выбор движка** — используйте набор агентов для Godot, Unity или Unreal (или не используйте ни один)

## Поддерживаемые платформы

Протестировано на **Windows 10** с Git Bash. Все хуки используют POSIX-совместимые паттерны (`grep -E`, а не `grep -P`) и включают запасные варианты для отсутствующих инструментов. Работает на macOS и Linux без модификаций.
